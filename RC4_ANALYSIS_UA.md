# GOODRAM Tender Intelligence 2.0.0-RC4

## Що підтверджено і виправлено

Це повний ZIP для заміни коду, не overlay. Усі надані модулі, профілі та попередні тести збережено. Функції RC3 для Apify відновлено за тією ж схемою зберігання (config/apify_encrypted, Fernet, DATA_DIR/.settings.key або SETTINGS_ENCRYPTION_KEY), оскільки у доступних вкладеннях була початкова база RC2, а не ZIP RC3. Dockerfile та приклади середовища включено.

### 1. Спільний збій Prozorro / Latvia / NEN / Slovakia / Lithuania

Підтверджена помилка app/net.py: HTTPX aiter_bytes() уже розпаковує gzip/deflate, але код створював нову Response з декодованим тілом і старим Content-Encoding. Конструктор повторно розпаковував звичайний JSON/HTML. На старому коді синтетична gzip-відповідь відтворила точний DecodingError: Error -3 while decompressing data: incorrect header check.
RC4 прибирає Content-Encoding, старий Content-Length і Transfer-Encoding перед створенням Response. Ліміт декодованого тіла збережено. Для GET/HEAD при справжній помилці декодування є одна повторна спроба з Accept-Encoding: identity; платний POST Actor через цю гілку не повторюється. Це виправляє підтверджений спільний дефект, але не підтверджує схеми кожного порталу наживо.

### 2. TED HTTP 400

Непідтримуване поле estimated-value-proc-currency замінено на estimated-value-cur-proc відповідно до перевіреної офіційної OpenAPI. Парсер також читає правильне поле валюти. Повний обмежений текст помилки доступний для узгодження полів; короткий текст залишається для показу. Узгодження читає JSON message, не втрачає назви з великими літерами/дужками, не повторює ідентичний набір і не погоджується на втрату ID/title/country. Повторні сторінки перевіряються окремо для кожного запиту. timedOut:true не приймається за успіх.

Офіційні джерела, перевірені під час підготовки:
- https://ted.europa.eu/api/documentation/api-docs
- https://docs.ted.europa.eu/api/latest/search.html
- https://www.python-httpx.org/quickstart/

Живий POST TED у цьому середовищі не підтверджено. Пряме отримання OpenAPI через HTTP-клієнт повернуло 403; документацію перевірено через веб-інструмент. Це не доказ блокування вашого Render.

### 3. Німеччина

У вашому логу API прямо відхиляє поточний pubDay. RC4 починає з учорашнього дня у Europe/Berlin, сканує до заданого ліміту минулих днів і показує current_day_excluded та requested_archive_days. Якщо вибрано лише сьогодні, запит архіву не робиться; статус not_available_yet. 25 review у вашому логу не означає збій завантаження: це записи для перевірки, їхні відсутні поля не вигадуються.

### 4. BZP / TenderNed

BZP у наданому логу вже зберіг 12 active. partial залишається чесним: 7-денний ліміт, ліміт сторінок і повторна сторінка не дозволяють стверджувати повне покриття. Коректність SearchAfter на живому BZP не підтверджено; курсор не замінено вигаданим API.
TenderNed отримав 150 записів, але всі відхилені фільтром not_relevant. Це не транспортний збій і не доказ відсутності релевантних закупівель поза першими сторінками. RC4 додає empty_reason і coverage_limited. Фільтри не послаблено штучно заради ненульового результату.

### 5. EKAP / Apify

Missing configuration означає, що на момент збору відсутні всі три значення. Токен сам по собі недостатній: потрібні Actor ID і Input JSON вашого Actor. У Settings > Apify / EKAP збережено захищене введення всіх трьох полів, шифрування, ENV fallback, збереження старого токена при порожньому полі, видалення, перевірки JSON та admin-only API. Додано список missing. Збереження не запускає Actor і не перевіряє його права; запуск може бути платним. Вихідну схему конкретного Actor треба перевіряти на реальному результаті.

### 6. Hungary EKR / Estonia RHR

Це окремі discovery_failed, а не gzip-збій. RC4 очікує появи реальних DOM-посилань/рядків замість лише фіксованої затримки; RHR після натискання пошуку повторно очікує посилання. EKR може спробувати браузер після звичайної HTTP-помилки, але не обходить login/CAPTCHA. Додано page_url, page_title, anchors, table_rows, iframes та browser/HTTP errors; ці дані тепер зберігаються і при винятку, а не губляться у generic coverage.

Важливо: це покращення очікування й діагностики, НЕ підтверджене повне виправлення живого збору EKR/RHR. Якщо поточний портал не віддає очікувані елементи, джерело залишиться discovery_failed. TED не підставляється замість національного порталу. У локальному browser-fixture прогоні Estonia не стартувала через browser_unavailable; Hungary пройшла через доступний HTML fallback, тому це не підтвердження браузерного рендерингу.

## Розгортання

1. Зробіть резервну копію SQLite і ключа шифрування. Замініть код репозиторію повним вмістом ZIP у корені, не видаляючи постійний диск.
2. Збережіть наявні ADMIN_TOKEN, DATA_DIR та SETTINGS_ENCRYPTION_KEY. Якщо ключ створено автоматично, збережіть DATA_DIR/.settings.key разом із базою. Не змінюйте ключ без міграції.
3. Docker: Root Directory порожньо, Dockerfile ./Dockerfile, Context ., Docker Command порожньо. Dockerfile включає встановлення Chromium. Один uvicorn worker.
4. Перевірте /health: version 2.0.0-RC4, build_id v200-transport-schema-rc4.
5. У Settings збережіть Admin token для сесії. Натисніть Load settings у Apify; перевірте всі три поля. Токен назад у браузер не повертається.
6. Запустіть нове оновлення джерел. Попередні діагностики RC3 не переписуються до нового збору. Перевірте нові timestamps, статуси й review.

На ефемерному диску redeploy може втратити базу, токен і ключ. render.yaml збережено з free-планом, без обіцянки persistence. Для стійкого зберігання потрібен persistent DATA_DIR. Не комітьте SQLite, .env чи .settings.key. Використовуйте HTTPS. Без ADMIN_TOKEN керування Apify заблоковане, але загальні старі write-операції можуть бути відкритими, тому ADMIN_TOKEN обов’язковий для публічного розгортання.

## Межі перевірки

57 основних локальних тестів пройшли: 26 базових, 14 native fixtures, 17 RC4. Додатково запущено 2 browser-fixture тести: Hungary пройшов через HTML fallback; Estonia завершився browser_unavailable. Отже, не всі тести повного набору успішні. Python compileall та node --check пройшли. Усі тестові дані синтетичні, HTTP/Actor відповіді змодельовані; у ZIP немає демонстраційних тендерів чи секретів.

Не виконано: Docker build, чиста інсталяція pinned dependencies, deploy на Render, живий збір усіх порталів, реальний/платний Actor, повна візуальна QA. Повну локалізацію не завершено. Джерела не позначено production-ready.
